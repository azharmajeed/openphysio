A session is "light" when its demand's `kind` is `"light"`; every other kind is hard. So a day holds at most one hard session, plus at most one light session (mobility / rehab). No session-type, exercise or weekday ids in logic.
3. 4. Demands that no longer fit are dropped by priority with a warning (the existing mechanism); the warning text says the daily or injury limit was the reason.
5. Tests: R0 knee profile: ≤ 1 hard session every day, ≥ 2 rest days a week, ≤ 4 hard sessions a week, every dropped demand has a warning. No-injury five-goal profile: ≤ 1 hard session a day, still meets AC-3 where it fits, warnings for the rest. Determinism per seed. Existing tests stay green (adjust only assertions that encoded the old 2-hard-a-day behaviour, and say which in the PR).
