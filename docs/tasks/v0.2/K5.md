Expected result:
Draft `VideoSegment` records that Azhar confirms by watching, so the "Why and how" sheet can play the right part of a trusted video.
1. Read each followed channel's public RSS feed (`https://www.youtube.com/feeds/videos.xml?channel_id=<id>`, the same source the app uses; no API key, no page scraping, no downloads, no transcripts).
2. For the 30 exercises in data/top-exercises.json (match by exercise name, aliases and the movement, e.g. "RDL" ↔ dumbbell_rdl), pick at most one or two candidate videos each where the title or description is clearly about that exercise or its technique.
3. Start/end: when the description has chapter timestamps for the exercise, use them; otherwise start at 0 and say "timestamp needed" in `review.notes`.
4. Each segment: YouTube video id, channel id, title (the video's title as metadata), a one-sentence summary in our own words of what the video covers according to its title and description only (never claims about content you haven't seen), subjects = exercise ids, `sourceId` → a `Source` record of type `video` (citation = channel + title, URL, licence "YouTube standard licence (embed only)").
5. Write to `data/video-segments/all.json` and `data/sources/videos.json` (register that one new source file in src/data.ts — the only code change). Every record `review.state: "draft"`.
6. Report exercises with no candidate: they simply show no video (AC-5 "where one exists").
